# AI proposals: prompt to reviewable scenarios

The local pilot supports OpenAI, Anthropic, Google Gemini and OpenCode Go scenario proposals. Generation uses supplied and explicitly selected context. A user supplies a testing request and relevant application context (requirements, known test IDs, paths and fixture rules). The provider returns proposed scenarios and questions; it cannot approve scenarios, execute test actions, fetch URLs, or edit an active run. OpenCode uses only its internal StructuredOutput return tool.

## API contract

`GET /api/ai/config` (operator auth) returns `providers:[{provider:"openai"|"anthropic"|"google", models:string[], managed_available:boolean, byok_available:boolean}]`. The legacy top-level `provider`, `models`, `managed_available`, and `byok_available` fields continue describing OpenAI for existing clients. Each model list comes from its own comma-separated `QA_OPENAI_MODELS`, `QA_ANTHROPIC_MODELS`, or `QA_GEMINI_MODELS`; an empty list disables that provider’s API-key proposals. IDs use only `[A-Za-z0-9._-]`, with at most 100 bytes and 20 models per provider. When local ChatGPT plan access is enabled, configuration also includes a display-only `chatgpt` status. Its models come from the selected account rather than this allowlist; see [the subscription contract](chatgpt-subscription.md). Managed mode additionally requires the corresponding server-local API key. Anthropic managed mode can use `QA_ANTHROPIC_WORKSPACE_ID`. Never return a key. This is technical credential routing, not a launched billing product.

`POST /api/projects/{id}/proposals` requires operator auth and JSON `{provider:"openai"|"anthropic"|"google"|"opencode-go", prompt:string, context:string, model:string, credential_mode:"managed"|"byok"|"chatgpt"|"opencode", consent:true}`. The selected provider/model pair must be configured; omitted `provider` preserves the OpenAI default for existing clients. ChatGPT mode requires OpenAI and also requires `chatgpt_profile_id` for the connected active account and a model returned by that account’s catalog; it rejects a provider-key header. Prompt is 1–4000 characters; context 1–60000. Consent explicitly covers sending this supplied material to the selected provider. Do not implicitly attach test credentials, existing browser state or arbitrary repository files. BYOK additionally supplies `X-QA-Provider-Key`; use it only for this request, without persistence or logging. Anthropic BYOK optionally supplies `X-QA-Anthropic-Workspace` when its key is not scoped to one workspace. The workspace must start with `wrkspc_` and use the same safe characters as model IDs; it is transient, forwarded as `anthropic-workspace-id`, and rejected for other providers or modes. It cannot be supplied in JSON. Credential modes and providers must not fall back to each other. Reject malformed/unknown fields, missing consent, missing credentials and missing project before any provider call.

Return 200 `{provider:"openai"|"anthropic"|"google"|"opencode-go", credential_mode:string, chatgpt_profile_id?:string, model:string, context_sha256:string, scenarios:ScenarioInput[], questions:string[], assumptions:string[]}`. All scenarios have `approved:false`; require 1–50 steps and at least one valid assertion for each proposal. Permit zero scenarios when context is insufficient, accompanied by focused questions. Bound output to at most 10 scenarios, 20 questions, 20 assumptions, and 4000 characters per question/assumption. Do not save proposals automatically; the user reviews, edits, then saves through existing scenario creation. Generation failures never produce invented success data.

Use 400 for invalid input, 404 for missing project, 503 for unconfigured access, 502 for invalid/refused/incomplete provider output or upstream failure, and 504 for provider timeout. API-key errors distinguish key/workspace/model access (403), provider request/schema rejection (502), quota/rate limits (429), and provider outages (503). Errors use fixed text and omit provider bodies, keys, prompts and context. Keep a 90-second provider deadline, request body limit 128KiB for this endpoint, and response limit 2MiB. Limit to two concurrent proposal calls per server; return 429 when busy. Cap API-key output tokens at 6000. ChatGPT subscription calls omit that unsupported field and accept only a complete successful streaming event. QA Agent does not retry automatically or make background model calls. OpenCode sessions abort on the first reported native retry, as documented and tested in the connection contract. Subscription errors distinguish reconnection (409), denied plan access (403), quota (429), temporary availability (503), and unsupported request capability (502).

## Implementation

Use three small typed adapters in `internal/planner` behind the single draft operation, sharing the deadline, HTTP response bounds and embedded JSON schema. API-key credential modes use the same operation with separate credential sources. See [exact provider contracts](provider-adapters.md). The ChatGPT subscription path binds requests to a protected local account session, fetches its model catalog, and decodes streamed Responses output before the same scenario validation. Use fixed official HTTPS endpoints with structured JSON output and no tools. OpenAI uses Responses with `store:false`; Anthropic uses Messages with `output_config.format`; Gemini uses GenerateContent with `generationConfig.responseFormat.text`. Refuse redirects. Validate actual output in Go with the existing scenario validator; required approval belongs to the user regardless of model output. Make transport injection available only for tests, without user-supplied endpoint URLs.

Prompt the model to treat supplied code/context as evidence rather than instructions, to distinguish known business expectations from guesses, and to ask questions instead of inventing selectors, credentials or expected values. This protects the approval boundary but does not make model suggestions authoritative.

Follow the official [Structured Outputs guide](https://developers.openai.com/api/docs/guides/structured-outputs). Handle completed, incomplete and refusal responses explicitly. Document configured model compatibility; no model access or live generation is verified merely by a fake-server test.

## Web flow

Add “Ask AI to propose” to the scenario area. Show provider, model and available managed/BYOK/ChatGPT choices from server configuration, a password field for a transient BYOK key, testing-request and app-context fields, and explicit consent to send those fields to the selected provider. Keep all keys in memory and clear the BYOK key and workspace fields on submission or provider/access-mode changes. Changing provider, model, account, credentials, prompt, context or selected sources cancels in-flight generation, removes stale drafts and resets consent. Display questions and assumptions beside draft outcomes. Let the user open proposals in the existing editor with approval initially off; saving approved scenarios still requires explicit review. Show unavailable/configuration errors honestly. Do not call this repo sync or live exploration.

## Proof

Test both credential modes through a fake HTTP provider, including redirection refusal, malformed/incomplete/refused output, invented action rejection, forced unapproved proposals, cancellation, output bounds, and timeout. Exercise API validation/auth without a provider key. A live paid provider check is conditional on an explicitly configured key; no key is currently assumed available.

The ChatGPT subscription integration adds signed synthetic OAuth callback tests and browser flow checks. These verify local security and persistence boundaries; live account admission and completed inference remain separate acceptance checks.

Provider contract tests cover all three adapters, with separate managed/BYOK routing, unsafe model rejection, Anthropic workspace routing, Gemini text-only responses, and local output bounds. The browser harness checks Anthropic/Gemini desktop/mobile controls, recipient consent, key/workspace clearing, quota without fallback, and unapproved draft persistence. It compares synthetic drafts against independently reviewed fixture requirements before running approved copies through the real worker on healthy and faulty apps. External generation in this harness is synthetic; live Anthropic/Gemini account admission remains conditional on test keys.

On 1 October 2026, local Go race tests against disposable PostgreSQL, static analysis, the web build, and the full browser harness passed. The harness verified both new provider flows and preserved ChatGPT behavior. Live Anthropic/Gemini inference was not verified because no test keys were supplied.

## OpenCode Go connection

Configuration adds `opencode_enabled:boolean`. Operator-only `GET /api/ai/opencode` returns `{enabled,connected,models:[{id,name}]}` from the dedicated runtime, restricted to Go text models with tool-call capability. `POST /api/ai/opencode/connect` accepts `{key}` (8192-byte request cap); OpenCode persists this key in its protected local data directory. `POST /api/ai/opencode/disconnect` removes it and invalidates the isolated runtime provider cache. Status never returns credentials.

Proposals use `provider:"opencode-go"`, `credential_mode:"opencode"` and an exact Go catalog model. Other provider keys, workspace headers and ChatGPT profiles are rejected. The request returns the existing proposal result with Go provenance and forced unapproved scenarios. Unknown/unavailable models fail before session creation. See [the full runtime, billing, cleanup and verification contract](opencode-go.md).
