# Bounded browser discovery

Discovery inventories observed pages and controls; it does not establish correctness. Observed text (including numbers) must never automatically become an expected business outcome. The model combines these observations with requirements and repository context to propose checks for human review.

`POST /api/projects/{id}/discoveries`: `{start_path: "/", max_pages: 1..5, setup_scenario_id?: string}` -> 202 Discovery. Optional setup must be an approved same-project scenario. Its full definition and the project's base URL are snapshotted. The worker executes those exact setup steps in a fresh context, then restricts requests to GET/HEAD/OPTIONS and follows only same-origin ordinary links. It does not click discovered buttons or submit discovered forms. GET routes may have side effects, so use designated test environments. Obvious signout/delete links, query strings, fragments and external links are excluded. No input values, cookies or browser storage are collected. The whole browser operation is bounded to 60 seconds and 40,000 bytes of observations.

`GET /api/projects/{id}/discoveries` -> latest 100 Discovery objects. `GET /api/discoveries/{id}` -> Discovery. `POST /api/discoveries/{id}/cancel` cancels queued/running work, rejects terminal cancellation with 409.

Discovery fields: `id`, `project_id`, `base_url`, `start_path`, `max_pages`, optional `setup_scenario` (full Scenario), `status` (queued/running/completed/error/cancelled), optional `result`, `error` (safe plain text, empty when absent), `created_at`, optional `started_at`, `finished_at`. Completed means observation finished, not tests passed. `result` is `{pages, limited, warnings}`. Page: `{path,title,headings:string[],elements:[{test_id,tag,role,label,text,input_type}],links:[{path,text}],truncated:boolean}`. Max five pages, 80 elements and links per page, 20 headings; strings/path bounds match `worker/src/discover.ts`. `limited` and warnings show partial coverage. Nonempty pages required for completed; result absent on errors.

Worker endpoints use existing worker authentication: `POST /api/worker/discoveries/claim` `{worker_id}` -> `{discovery: Discovery, lease_token, lease_expires_at}` or 204; `POST /api/worker/discoveries/{id}/heartbeat` `{lease_token}` -> lease_expires_at; `POST /api/worker/discoveries/{id}/complete` `{lease_token,result?,error?:string}` -> Discovery. Exactly one result or nonempty error required, max error 500 bytes. The server validates worker output, returns 409 for expired/cancelled leases, and derives status. Claim uses the same 60-second lease/20-second heartbeat policy as test runs. Expired running work becomes error; no automatic replay of setup actions.

Proposal input gains optional `discovery_id`. It must reference a completed discovery for this project. Server appends the snapshotted observation (explicitly labelled untrusted observations, not business expectations) before final context validation. Context can be supplied through manual text, repository snapshots, discovery, or a combination; total remains at most 60,000 bytes and explicit consent remains required. Proposal response gains optional `discovery_id` for traceability. Browser discovery itself makes no model calls and requires no model key.
